# Contributing

Open an issue with a reproducible code defect, an open dataset whose EEG waveform acquisition is relevant to around-ear sensors, or a proposed numerical test. State what observation would change the conclusion. Include source URL/version, sampling rate, units, geometry/reference and accessible license metadata. No participant names, private recordings, credentials or health histories in issues.

For code changes, use a branch and pull request. Run the focused tests and any affected experiment checks. Preserve prior release artifacts; a changed input, preprocessing rule or model is a new protocol/version. Review numerical claims against exact generated artifacts and show numerator, denominator and group. Planned experiments remain planned until actual receipts exist; failed and null outcomes are publishable.

The current program focuses on anonymous voltage pattern discovery and numerical agreement. Semantic, clinical and independent-replication projects are outside its current execution scope. Hardware compatibility needs actual acquisition evidence; a resampled public recording does not prove a device mapping.

For catalog changes, preserve all prior releases and original source receipts. Add an explicit, hash-bound input manifest; reject identity or checksum conflicts instead of replacing rows. Rebuild into a new destination and compare the exact logical rows, database hash and source-hour totals. Retain every missing primary endpoint and its original correction family. A catalog rebuild must not trigger wave acquisition, model inference or detector regeneration.

For new scientific data or methods, freeze the source selection, quality rules, grouping and analysis before access. Keep provenance and evaluation labels separate from numerical discovery inputs. A new public dataset is not evidence of physical headset equivalence, and unknown model-pretraining overlap remains unknown.
