The REVE HF usage example does **not** specify an input voltage unit or new-recording scaling. Its [pretraining loader](https://github.com/elouayas/reve_eeg/blob/06a7059a07c3dabd80aee60c3dbc1eca4bdbe1c7/src/utils/data_loading.py#L694-L717) subtracts stored per-recording/channel means, divides by stored standard deviations, and clips to ±15. Applying an arbitrary scale to our data would be an unsupported choice.

CodeBrain's [paper §3.1](https://arxiv.org/html/2506.09110v4) reports TUH/TUEG as its pretraining source, about 9,246 hours, without a recording-level identity audit against these targets. REVE's [paper Table 7](https://arxiv.org/html/2510.21585v1) reports 56 OpenNeuro sources among 92 datasets. Its [released open subset card](https://huggingface.co/datasets/brain-bzh/reve-dataset/blob/main/README.md) lists none of the four target IDs, but covers only about half the corpus. Absence from that card does not establish zero overlap. Neither source proves a target is independent of pretraining.

The pinned `ds005178` export supplies μV units, average reference, and `RB RT LB LT` order, but absolute contact coordinates are unknown. The existing baseline uses label-blind numeric features; no pretrained model has run. No Neurable recording has passed this EEGT qualification contract. The lead’s subsequent read-only engineering-source check found historical Kit/wire evidence with unresolved physical units and sample-clock calibration; see the [availability recheck](../protocol/neurable-availability-recheck-2026-09-25.json). Consumer focus summaries and excluded private waveforms are not audit inputs.

## Execution verdict and minimum next test

- **CodeBrain:** A frozen **EEGSSM backbone only** is a plausible mechanical test on `ds005178` without fabricating electrode coordinates: resample 250→200 Hz, form 30-second `[1,4,30,200]` patches, use the documented μV/100 scale and the supplied channel order. The learned 19-channel spatial kernel makes transfer quality unknown. The full released tokenizer has unresolved positional-ID mapping for ear contacts. Also, [EEGSSM calls `.cuda()` on its attention mask](https://github.com/jingyingma01/CodeBrain/blob/22d350caf68246d2fda4f630ef837420db3fb130/Models/SSSM.py#L113-L132), so the unmodified code cannot run directly on this Mac's CPU/MPS. No checkpoint load was tested.
- **REVE:** A faithful run on the four `ds005178` channels is **blocked** by absent exact bank names and unknown 3D contact positions. For `ds004015` and `ds005207`, exact channel-to-bank matching or measured coordinates and a justified normalization remain unverified. Resampling alone does not resolve this.

**Next planned software test:** On a CUDA-capable host, load only the official `CodeBrain.pth` (60,901,006 B; LFS SHA-256 `d9714b8732c9883a04d022ee66254cd578ae1fa27f5458e6ab7f1aa96e9a7352`) in a frozen `SSSM(if_codebook=false)`, feed one pinned `ds005178` 30-second segment prepared as above, and verify strict weight loading, output shape, and finite values. This is a software/format smoke, not evidence of accuracy or semantic meaning. REVE's first prerequisite is an authoritative 3D coordinate map for `RB RT LB LT` and an explicit new-recording normalization choice. Resolve provenance overlap before interpreting any future benchmark score.

The two official repositories had no GitHub Release assets indexed in this audit. A similarly named third-party REVE port was excluded; its architecture cannot substitute for the author weights.
